# Chat rendering, collapsing, and scrolling improvements

The tailored `showcase` chat now exists at `/showcase/single`, using the normal chat rendering components. Its examples are generated by `showcase/reset.mjs`. This is a review ground for all chat elements' rendering decisions and appearance—not just scrolling.

Rendering changes below remain ideas for future work. Discuss them with the user before implementing; avoid starting work without enough budget to finish.

## Existing showcase examples

- Markdown formatting, tables, Internet links, and local file links.
- Short and long prose, code blocks, and horizontally overflowing content.
- Tool outputs of varied lengths, including 10- and 11-line collapse-boundary cases.
- A screenshot-tool result reproducing the problematic case where the Show more control takes as much space as the hidden content.
- Code-block diffs and a large recorded edit diff with sparse changes and a larger replacement.
- Thinking, ANSI-colored output, and a tool error.
- Adjacent image examples: a plain attachment-style file path, a user message with an embedded image, and a read tool image result.

These are static synthetic records. The displayed tool calls were not executed. Resetting replaces the showcase history, including discussions added to it; stop Spicy before resetting to avoid stale in-memory history.

## Presentation modes to discuss

- Show all content without collapsing.
- Show all content within a scrollable block (`overflow: scroll`).
- Collapse the middle, preserving the beginning and end.
- For code diffs, provide a diff-aware middle-collapse mode: prioritize showing changed lines, up to a point, and collapse unchanged context rather than simply preserving the beginning and end. Exact limits remain undecided.

## When not to collapse

- Do not collapse when the collapsed presentation would occupy nearly as much space as the full content.
- Include the space occupied by collapse controls in that comparison, especially when controls reserve an entire line.
- Use the near-threshold showcase examples to review this problem before deciding behavior.
